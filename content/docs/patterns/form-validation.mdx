---
title: Form Validation
description: How to surface field-level errors consistently across forms.
---

Form validation is a pattern, not a component — it's the consistent way
[Input](/docs/components/input), [Label](/docs/components/textarea), and
error text combine whenever a field fails validation.

## Anatomy

1. The field's `Input` gets `aria-invalid` so it picks up the destructive
   border/ring style automatically.
2. The `Label` stays neutral — don't recolor it; the input itself signals
   the error.
3. A single line of error text appears directly under the field, in
   `text-destructive`, replacing (not stacking with) the field's helper text.
4. On submit, focus moves to the first invalid field.

## Usage

```tsx
import { Input, Label } from "@nimbus/ui"

export function EmailField({ error }: { error?: string }) {
  return (
    <div className="grid gap-2">
      <Label htmlFor="email">Email</Label>
      <Input id="email" type="email" aria-invalid={!!error} />
      {error ? <p className="text-sm text-destructive">{error}</p> : null}
    </div>
  )
}
```

## Guidance

- Validate on blur, not on every keystroke — re-validate on change only
  *after* a field has already been marked invalid once.
- Never rely on color alone: the error text itself, not just a red border,
  carries the meaning (accessibility).
- For whole-form errors that aren't tied to one field, use
  [Alert](/docs/components/alert) with `variant="destructive"` above the
  form, not a floating toast.
