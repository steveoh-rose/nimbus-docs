---
title: Confirmation Flow
description: When and how to confirm a destructive or hard-to-reverse action.
---

Not every action needs a confirmation step — over-confirming trains users to
click through dialogs without reading them. This pattern defines when to ask,
and how, using [Dialog](/docs/components/dialog).

## When to confirm

| Action | Confirm? |
| --- | --- |
| Deleting a single item, reversible via undo | No — use an undo toast instead |
| Deleting a resource with no undo (e.g. a connection) | Yes |
| Leaving a page with unsaved changes | Yes |
| Toggling a setting | No |

## Anatomy

1. **Title** states the action in the imperative: "Delete connection?" not
   "Are you sure?".
2. **Description** names the specific resource and states that it's
   irreversible, if true.
3. **Two actions**: a neutral "Cancel" (`variant="outline"`) and the
   destructive confirm (`variant="destructive"`), in that left-to-right
   order, matching this site's own [Dialog](/docs/components/dialog) demo.
4. The confirm button's label repeats the verb ("Delete", not "OK" or "Yes").

## Usage

```tsx
import { Button, Dialog, DialogClose, DialogContent, DialogDescription, DialogFooter, DialogHeader, DialogTitle, DialogTrigger } from "@nimbus/ui"

export function DeleteConnectionDialog({ name }: { name: string }) {
  return (
    <Dialog>
      <DialogTrigger asChild>
        <Button variant="destructive" size="sm">Delete</Button>
      </DialogTrigger>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>Delete {name}?</DialogTitle>
          <DialogDescription>
            This permanently removes the connection. This can&apos;t be undone.
          </DialogDescription>
        </DialogHeader>
        <DialogFooter>
          <DialogClose asChild>
            <Button variant="outline">Cancel</Button>
          </DialogClose>
          <Button variant="destructive">Delete</Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  )
}
```
