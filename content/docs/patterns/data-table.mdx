A compound component combines several primitives — here, [Table](/docs/components/table)
and [Badge](/docs/components/badge) — into a ready-to-use organism for a
common product screen: a list of records with a status indicator.

<ComponentPreview name="data-table" />

## Usage

```tsx
import { Badge, Table, TableBody, TableCell, TableHead, TableHeader, TableRow } from "@nimbus/ui"

const statusVariant = {
  active: "default",
  provisioning: "secondary",
  degraded: "destructive",
} as const

export function ConnectionsTable({ connections }: { connections: Connection[] }) {
  return (
    <Table>
      <TableHeader>
        <TableRow>
          <TableHead>Name</TableHead>
          <TableHead>Status</TableHead>
        </TableRow>
      </TableHeader>
      <TableBody>
        {connections.map((row) => (
          <TableRow key={row.id}>
            <TableCell>{row.name}</TableCell>
            <TableCell>
              <Badge variant={statusVariant[row.status]}>{row.status}</Badge>
            </TableCell>
          </TableRow>
        ))}
      </TableBody>
    </Table>
  )
}
```

## What makes this "compound" rather than a primitive

Nothing here is a new component to import — it's a documented, reusable
*composition* of `Table` + `Badge` + a status-to-variant mapping. Product
teams copy this pattern instead of reinventing the status-color mapping each
time a new table is built. Real-world versions would add sorting, pagination,
and row actions built from [Dropdown Menu](/docs/components/dropdown-menu).
