title: Empty States
description: How to design the "nothing here yet" state for lists and tables.
---

Every list, table, or search result needs a designed empty state — the
default of a blank white box reads as broken, not empty.

<ComponentPreview name="empty-state" />

## Anatomy

1. **Icon or illustration** — a muted, simple visual, not decorative clutter.
2. **One-line explanation** — what's missing and why (bold, short).
3. **Supporting text** — one sentence, optional, explains what to do next.
4. **Primary action** — the single next step, as a `Button`, if one exists.

## Guidance

- Never show a bare "No data" string — always pair it with a next action
  when one exists.
- Distinguish **empty** (nothing created yet) from **no results** (a filter
  or search matched nothing) — the copy and action should differ: "Create
  your first X" vs. "Clear filters".
- Use [Skeleton](/docs/components/skeleton) for the *loading* state, not this
  pattern — empty states are for after loading completes with zero results.

## Usage

```tsx
import { Button } from "@nimbus/ui"
import { InboxIcon } from "lucide-react"

export function EmptyState() {
  return (
    <div className="flex flex-col items-center gap-3 rounded-lg border border-dashed p-10 text-center">
      <InboxIcon className="size-6 text-muted-foreground" />
      <p className="font-medium">No connections yet</p>
      <p className="text-sm text-muted-foreground">
        Create your first connection to start routing traffic.
      </p>
      <Button size="sm">New connection</Button>
    </div>
  )
}
```
