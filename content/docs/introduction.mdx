Nimbus UI is ConsoleConnect's design system — a set of design tokens, accessible
React components, and higher-level patterns used to build consistent products
across the company.

This site is the design-system documentation layer on top of the
[`nimbus-ui`](https://github.com/ConsoleConnect/nimbus-ui) component library.
It's organized into three layers, from smallest building block to largest:

## Tokens

The raw design decisions — color, typography, spacing, radius, shadows, and
motion — that every component is built from. See [Tokens](/docs/tokens/color).

## Components

Accessible, themeable primitives: buttons, inputs, overlays, navigation, data
display, and feedback. See [Components](/docs/components/button).

## Patterns

Everything built by combining primitives — organisms and templates like data
tables, command menus, and auth cards, ready to drop into a page, alongside
recipes for recurring UX problems like empty states, form validation, and
confirmation flows. Some patterns are copy-paste-ready composed components;
others are guidance and code rather than a single importable component. See
[Patterns](/docs/patterns/empty-states).

## Relationship to Storybook

`nimbus-ui`'s Storybook instance (still available at
[consoleconnect.github.io/nimbus-ui](https://consoleconnect.github.io/nimbus-ui/))
remains the source of truth for exhaustive per-prop API exploration and visual
regression testing. This site is the narrative layer on top — how to think
about the system, when to reach for which piece, and how pieces combine.

## Placeholder content notice

This scaffold currently renders the **shadcn/ui primitives** as stand-ins for
real `nimbus-ui` components so the whole site, navigation, and preview
pipeline can be reviewed end-to-end before wiring up real package access.
Swapping in real components is a matter of changing the imports inside
`src/registry/demos/*.tsx` — nothing else in the docs pipeline needs to change.
